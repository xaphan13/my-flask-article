## ADV-001: Враждебный прогон по /art/<author>/<art_id> — изменение работает штатно на всех проверенных краевых значениях

- Session: задание «страница 404 для несуществующих статей»
- Suggested severity: LOW

What I did (все запросы с `-m 3` таймаутом, в одну сессию):

1. Базовые корректные и некорректные идентификаторы:
   - `GET /art/Max/1` → 200
   - `GET /art/Max/5` → 200
   - `GET /art/Max/999` → 404
   - `GET /art/Max/0` → 404
   - `GET /art/Max/-1` → 404
2. Краевые/нечисловые `art_id` (роут `<int:art_id>` отвергает всё не-int на уровне маршрутизатора, поэтому такие запросы даже не доходят до `abort(404)` — это нормально):
   - `GET /art/Max/99999999999999999999999` (24 девятки) → 404
   - `GET /art/Max/01` → 200 (валидный int 1, есть в словаре)
   - `GET /art/Max/+5` → 404 (Werkzeug int-конвертер не принимает `+`)
   - `GET /art/Max/1.5` → 404
   - `GET /art/Max/%201` (ведущий пробел) → 404
   - `GET /art/Max/0x1` → 404
   - `GET /art/Max/1e5` → 404
   - `GET /art/Max/4294967296` (2^32) → 404
   - `GET /art/Max/2147483648` (2^31) → 404 (дошёл до хендлера, `abort(404)` сработал)
   - `GET /art/Max/-2147483648` → 404
   - `GET /art/Max/-2147483649` → 404
3. URL-кодирование в `art_id`:
   - `GET /art/Max/0%2F1` → 404
   - `GET /art/Max/%2E%2E` → 404
   - `GET /art/Max/%00` → 404
   - `GET /art/Max/%0A` → 404
4. Странный `author` (роут `<string:author>` принимает всё без `/`):
   - Unicode `Юрий` (`%D0%AE%D1%80%D0%B8%D0%B9`) → 200
   - Китайский `作者` (`%E4%BD%9C%E8%80%85`) → 200
   - Арабский `المؤلف` (`%D8%A7%D9%84%D9%85%D8%A4%D9%84%D9%81`) → 200
   - Эмодзи `😀🚀` (`%F0%9F%98%80%F0%9F%9A%80`) → 200
   - HTML/XSS-попытка `<script>alert(1)</script>` (`%3Cscript%3Ealert(1)%3C%2Fscript%3E`) → 404 — Werkzeug отказался маршрутизировать из-за декодированного `%2F` в `</script>`, который ломает сегменты пути; это поведение Werkzeug, не хендлера.
   - HTML-теги без внутреннего `/` — `<script>` (`%3Cscript%3E`), `<` (`%3C`), `>` (`%3E`) → 200 (автор из URL в шаблон не выводится — см. п. 6)
   - SQL-инъекция-вид `' OR 1=1--` (`%27%20OR%201%3D1--`) → 200 (нет SQL-запроса по этому полю)
   - Path-traversal `\..\..\etc` (`%5C..%5C..%5Cetc`) → 200 (нет чтения файлов по этому полю)
   - Длинный автор 5000 'a' → 200
   - Кавычки `"'` (`%22%27`) → 200
6. XSS-анализ: шаблон `flaskblog/templates/new_art/art_author.html` выводит `{{ art.author }}`, где `art` — это запись из YAML `articles.yaml`, а не значение из URL. Значение `author` из URL попадает только в лог (`logFC.info(...)`). В теле ответа `<script>alert(1)</script>` в исходной форме не появляется — эксплуатация невозможна.
7. HTTP-методы на `/art/Max/1`:
   - `HEAD` → 200
   - `OPTIONS` → 200
   - `POST` → 405
   - `PUT` → 405
   - `DELETE` → 405
   - `PATCH` → 405
   - `POST /art/Max/999` → 405 (метод отвергнут раньше, чем хендлер)
8. Заголовки `Accept` на `/art/Max/1`:
   - `Accept: text/html` → 200
   - `Accept: application/json` → 200
   - `Accept: text/xml` → 200
   - `Accept: ../../etc/passwd` → 200 (заголовок не влияет на отдачу — всегда HTML)
9. Запросы сразу после «нештатных» (`GET /art/Max/1` сразу после серии 404/методов) → 200, без деградации.
10. Конкурентный пакет из 10 запросов `/art/Max/100..109` — все 10 вернули 404, ни один не упал и не оставил следов в логе.
11. Регресс соседних маршрутов:
    - `GET /` → 302 (редирект на `/art_home`, как и до изменения)
    - `GET /home` → 302 (редирект на `/art_home`, как и до изменения)
    - `GET /about` → 200
    - `GET /art_home` → 200
    - `GET /login` → 200
    - `GET /register` → 200
    - `GET /createDB` → 200
    - `GET /createDB/1` → 200
12. Тело 404: `GET /art/Max/999` отдаёт кастомную страницу `errors/404.html` («Oops. Page Not Found (404)»/«That page does not exist…»), обёрнутую в `layout.html` (Bootstrap-разметка, футер с переключателем темы присутствует).
13. Лог `./log/FLASK.log` после всех запросов:
    - По `art_author` нет ни одной записи уровня `ERROR`, ни одного `Traceback`, ни одного `KeyError`. Все запросы, включая 404, корректно отражены на уровне `INFO`.
    - Все 404-е ответы пришли от приложения чисто, без шума в логе.

Expected: для несуществующего `art_id` — штатный 404 (а не 500/трейсбек); для существующего — 200 без изменений; соседние маршруты не задеты.

Actual: ровно это и происходит. Все краевые/некорректные значения `art_id` (не-int, отсутствует в словаре, отрицательные, нулевые, очень большие) дают 404; существующие `art_id` (1, 5) дают 200 с тем же содержимым, что и раньше; соседние маршруты работают штатно. В логе нет ни одного трейсбека после серии враждебных запросов.

Замечание для триажа (не находка): `{{ art.content|safe }}` в `art_author.html` рендерит содержимое файла статьи без экранирования. Это **существующее** поведение, не связанное с изменением по этому заданию, и не эксплуатируется через URL (источник — статический файл в `templates/content_art/`). Вне рамок.
