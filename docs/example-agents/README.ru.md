# Personal Space

Личный менеджер знаний по мотивам Notion — страницы, блоки, базы данных с видами
таблица / доска / список — построенный автономно командой агентов Qwen Code.

- [REQUIREMENTS.md](./REQUIREMENTS.md) — что именно строится, по фазам, с критериями успеха.
- [AGENTS.md](./AGENTS.md) — правила сборки: роли команды, процесс работы с дефектами, форматы файлов.
- [QWEN.md](./QWEN.md) — инструкции оркестратора для основной сессии Qwen Code.
- `.qwen/agents/` — определения пяти агентов (orchestrator, два разработчика, qa, adversary).
- `.qwen/settings.json` — настройки Qwen Code на уровне проекта.

## Запуск сборки

Предварительные требования: Docker и VS Code с расширением Dev Containers.

1. Положите API-ключ в `.env` в корне репозитория (он в gitignore). Qwen Code поддерживает
   несколько провайдеров; наиболее частые — DashScope (Alibaba Cloud) и любой
   OpenAI-совместимый эндпоинт:

       DASHSCOPE_API_KEY=sk-...
       # или, для OpenAI-совместимого провайдера:
       # OPENAI_API_KEY=sk-...
       # OPENAI_BASE_URL=https://your-endpoint/v1

   Используйте отдельный ключ с лимитом расходов — агенты работают без присмотра против платных
   моделей.

2. Откройте эту папку в VS Code и переоткройте её в контейнере: нажмите **Reopen in Container**
   в уведомлении, которое VS Code показывает при обнаружении `.devcontainer`, или откройте
   палитру команд (Cmd+Shift+P) и выполните **Dev Containers: Reopen in Container**. То же меню
   находится за индикатором `><` в левом нижнем углу окна. Первая сборка занимает несколько
   минут: setup устанавливает Qwen Code и headless-браузер для сквозных тестов. Ключ
   внедряется при создании контейнера, поэтому после изменения `.env` выполните
   **Dev Containers: Rebuild Container**, чтобы он подхватился.

3. В терминале контейнера запустите Qwen Code:

       qwen-code

   Qwen Code автоматически читает `QWEN.md` — этот файл указывает основной сессии действовать
   как оркестратор. Используйте `/model` для выбора модели (например, `qwen-max` через
   DashScope или любую OpenAI-совместимую модель). Оркестратор делегирует субагентам, описанным
   в `.qwen/agents/`.

4. Запустите его командой:

   > Выполни весь проект, как указано, и не останавливайся, пока не будут выполнены все
   > критерии успеха и продукт не будет запущен

Пока он работает: дефекты появляются в `DEFECTS.md`, находки adversary — в
`ADVERSARIAL_REVIEW.md`, доказательства — в `screenshots/`, сквозные тесты — в `e2e/`. Когда
приложение запустится, VS Code переадресует его порт — откройте его в своём браузере, чтобы
смотреть и пользоваться продуктом.

## Использование разных моделей для разных агентов

Каждый агент в `.qwen/agents/` по умолчанию имеет `model: inherit`, то есть использует ту же
модель, что и основная сессия. Чтобы назначить разные модели разным агентам, измените поле
`model` во frontmatter агента. Поддерживаемые значения:

- `inherit` — та же модель, что у основной сессии (по умолчанию).
- `fast` — настроенная быстрая модель (через `/model --fast`).
- Идентификатор модели, например `qwen-max` — разрешается через провайдера основной сессии.
- `openai:gpt-4o` — явный провайдер и модель, полезно, когда агент должен работать на другом
  провайдере.
