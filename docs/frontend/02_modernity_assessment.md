# 02 — Насколько современен подход

> Оценка фронтенд-слоя по состоянию на 2026-08-28 (ветка `auto-md`, HEAD `0d258f5`).
> Вердикт: **архитектурный подход современный, инструменты — устаревшие**.
> Подход «серверный рендеринг + Jinja» для контентного сайта правильный; набор
> библиотек и часть практик застряли в 2017-2018 годах.

## 1. Общая оценка

| Критерий | Оценка | Обоснование |
|---|---|---|
| Парадигма (SSR вместо SPA) | 5 / 5 | Jinja-рендеринг идеален для статей: SEO, скорость первого отклика, нет клиентского состояния |
| Иерархия шаблонов Jinja | 4 / 5 | единый `layout.html`, партиалы, макрос футера; дублирование разметки форм (12 копий блока) |
| Актуальность CSS-фреймворка | 1 / 5 | Bootstrap 4.0.0 — первая версия 2018 года, EOL-линейка |
| Актуальность JS-библиотек | 1 / 5 | jQuery 3.2.1 (2017) и Popper 1.12.9 (2017) — устарели и не нужны |
| Качество собственного JS | 2 / 5 | работает, но inline onclick, глобальные функции, сломанный сайдбар, полный бандл highlight.js |
| Темы (светлая/тёмная) | 3 / 5 | работает через смену CSS-файла; устаревший механизм против CSS-переменных |
| Доступность и семантика | 2 / 5 | нет skip-link, aria, alt у аватара; мобильное меню не работает |
| Производительность загрузки | 2 / 5 | 5 внешних CDN-запросов, рендер-блокирующие скрипты, статика через Flask вместо nginx |
| Безопасность фронтенда | 3 / 5 | SRI есть на 4 из 6 внешних ресурсов; нет CSP; `{{ art.content|safe }}` на доверенных файлах |

**Практический итог.** Две из четырёх библиотек фронтенда не используются
собственным кодом вовсе (jQuery, Popper), третья (Bootstrap 4.0.0) — устаревшая
линейка с известными исправленными уязвимостями. Все три снимаются одним
переходом на Bootstrap 5.3.x.

## 3. Устаревшие практики и конкретные дефекты

### 3.1 Мобильная навигация не работает (HIGH)

В `includes/_header.html` объявлен `<div class="collapse navbar-collapse"
id="navbarToggle">`, но **нет кнопки-тогглера** `<button class="navbar-toggler"
data-toggle="collapse" data-target="#navbarToggle">`. На экранах уже `md` меню
схлопнуто Bootstrap'ом, а развернуть его нечем — навигация на мобильных
недоступна. Bootstrap JS при этом загружается.

### 3.2 Сломанный smooth-scroll сайдбара (MEDIUM)

`scripts.js:29-37`:

```javascript
document.querySelectorAll('.sidebar a').forEach(anchor => {
    anchor.addEventListener('click', function (e) {
      e.preventDefault();
      document.querySelector(this.getAttribute('href')).scrollIntoView({...});
    });
});
```

Пункты сайдбара в `includes/_sidebar.html` имеют `href="#"`, поэтому
`document.querySelector('#')` бросает `SyntaxError: '#' is not a valid selector`.
Клик «молча» не работает (default уже отменён), в консоль падает исключение.
Сам сайдбар — заглушка («Раздел 1/2/3»), т.е. функциональности нет вообще.

### 3.3 Классы Bootstrap 5 при Bootstrap 4 (LOW-MEDIUM)

В `includes/_footer_macro.html` используются `text-body-secondary` — утилита,
появившаяся только в Bootstrap 5. При подключённом Bootstrap 4.0.0 класс ничего
не стилизует: цвет текста подвала остаётся наследуемым, от задуманного серого
ничего нет. Класс `mt-align-items-center` в `layout.html:33` — опечатка, такого
класса нет ни в одном фреймворке (вероятно, задумывался `align-items-center`).

### 3.4 Тема переключается сменой файла CSS (MEDIUM)

Механизм «два файла тем + JS подменяет `href`» работает, но устарел:

- `light-theme.css` не подключён в HTML — тема определяется только JS, при
  отключённом JS сайт всегда тёмный;
- восстановление темы происходит в конце `body` — возможна «вспышка» темы;
- дублирование правил: два CSS-файла почти одинаковы, расходятся только цветами;
  любой будущий стилевой твик придётся вносить в три файла.

Современный подход — CSS-переменные (design tokens) + атрибут `data-theme` на
`<html>` (или нативная `prefers-color-scheme` / `data-bs-theme` у Bootstrap 5).

### 3.5 Собственный JS — стиль 2010-х

- `onclick="toggleTheme()"` в шаблоне — inline-обработчик: нет CSP-совместимости,
  функция обязана быть глобальной.
- `hljs.highlightAll()` — полный бандл highlight.js (все языки, ~1 МБ) грузится
  на каждую страницу, включая страницы без кода.
- Никаких модулей, `defer`, минификации — `scripts.js` отдаётся как есть.
- Тема подсветки кода (`github-dark`) фиксирована и не следует за темой сайта.

### 3.6 Загрузка ресурсов и CDN

- 5 внешних запросов к 3 CDN (`maxcdn.bootstrapcdn.com`, `code.jquery.com`,
  `cdnjs.cloudflare.com`) — три источника вместо одного, без локальных копий:
  при недоступном CDN сайт остаётся без стилей и без навигации.
- `integrity` (SRI) есть у jQuery, Popper и Bootstrap (CSS+JS), но **нет** у
  highlight.js (CSS и JS).
- Скрипты грузятся в конце `body` без `defer`/`async` — для jQuery/Popper/
  Bootstrap JS это рендер-блокирующая загрузка ~230 КБ.
- Статика отдаётся через Flask (`/static/*`), nginx проксирует всё в приложение —
  воркер Python тратится на раздачу неизменяемых файлов, кэш-заголовков нет.

### 3.7 Доступность, семантика, SEO

- `<html lang="ru">` есть — хорошо.
- Аватар в `account.html` без `alt`.
- Нет skip-link, нет `aria-current` у активных пунктов меню.
- Заголовок статьи — `<h3>` со ссылкой на главную (`art_author.html:6`), на
  странице нет ни одного `<h1>`; для SEO и доступности заголовок должен быть
  `<h1>`.
- Нет `<meta name="description">`, Open Graph, favicon.
- Смешение языков интерфейса: `Articles` / `Account` / `Logout` / `Login` /
  `Register` / `About` рядом с русскими `Управление` / `Тема` и русским контентом.

## 4. Что сделано хорошо (чтобы не переписывать зря)

- **Единая иерархия шаблонов** — один `layout.html`, партиалы и макрос футера;
  это современная и чистая структура (в документации 01/02/04/05 описаны две
  иерархии, но в текущем дереве их нет — расхождение уже устранено фактически).
- **`url_for('static', ...)`** вместо хардкода путей (кроме JS-файла, где пути
  тем захардкожены `/static/art_css/...` — стоит поправить).
- **Системные шрифты** — нет лишних веб-шрифтов, это хорошо для скорости.
- **`{{ art.content|safe }}`** — осознанное исключение из экранирования для
  доверенных файлов; риск появится только при пользовательском контенте.
- **SRI на части ресурсов** — половина внешних скриптов защищена целостностью.
- **`viewport`-мета** присутствует.

## 5. Итоговая оценка современности

| Уровень | Оценка |
|---|---|
| Парадигма и структура шаблонов | современные (2020-е) |
| Библиотеки | устаревшие (2017-2018) |
| Собственный JS | устаревший стиль (inline, глобальные функции) |
| Темы | устаревший механизм (смена файлов вместо CSS-переменных) |
| Доставка статики | устаревшая (CDN без бандла, Flask вместо nginx) |

Фронтенд — самый отстающий слой проекта: backend использует Flask 3.1 / Pydantic 2
(актуальные), а фронтенд — стек середины 2010-х. При этом «модернизация» не
требует переписывания: достаточно обновить Bootstrap до 5.3, удалить jQuery/Popper,
починить два JS-дефекта и навести порядок с CDN и статикой. Детали — в
[`03_improvements.md`](03_improvements.md).
