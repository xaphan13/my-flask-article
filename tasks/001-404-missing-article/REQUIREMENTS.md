# Страница 404 для несуществующих статей

## Суть

Сейчас запрос несуществующей статьи (`/art/<любой-author>/999`) бросает `KeyError` из
`art_dict_file[art_id]` в `art_author` и выливается в **500** с трейсбеком. Нужно,
чтобы несуществующая статья давала штатную **404**-страницу проекта, а существующие
статьи открывались как раньше.

Это первое простое задание агентного режима: цель — прогнать полный цикл команды
(план → backend → qa → adversary → дефекты → закрытие) на маленьком, хорошо понятном
улучшении.

## Что сделать

- В `flaskblog/new_articles/routes_articles.py` обработать отсутствие `art_id` в
  `art_dict_file`: вместо падения с `KeyError` — `abort(404)`.
- Не менять поведение существующих маршрутов; `/art/<author>/<art_id>` для валидного
  `art_id` работает как раньше.
- Шаблон 404 уже есть (`errors/404.html`, рендерится app-wide обработчиком) — новых
  шаблонов не требуется; если текст страницы нужно уточнить под случай «статья не
  найдена», это согласовывается с оркестратором.

## Вне рамок

- Не трогать декоративность `author` в URL (известная особенность, отдельное задание).
- Не трогать схему `schema_art.py` и YAML статей.
- Не добавлять тестовые фреймворки — проверки делаются запуском приложения и curl.

## Критерии успеха

Каждый критерий должен быть продемонстрирован доказательством — curl-выводом,
скриншотом или логом, — а не просто заявлен.

1. `curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:5000/art/Max/999` возвращает
   `404` (при запущенном приложении), тело — штатная страница 404 проекта.
2. Существующая статья (`/art/Max/1`) по-прежнему возвращает `200` и её содержимое.
3. `/art_home` и `/` работают как раньше (`200`, перенаправление соответственно).
4. В логе приложения нет трейсбека `KeyError` при запросе несуществующей статьи.
5. `uv run ruff check .` проходит без новых замечаний.
6. `python -c "from flaskblog import create_app; print(len(list(create_app().url_map.iter_rules())))"`
   по-прежнему печатает `13`.
7. Скриншот страницы 404 в `screenshots/` приложен и визуально проверен (обе темы,
   если переключение темы доступно на этой странице).

## Финальные критерии

Задание закрыто, когда:

- Все семь критериев выше подтверждены доказательствами.
- Проведён adversarial-прогон по изменённому маршруту; каждая находка в
  ADVERSARIAL_REVIEW.md исправлена или отклонена с письменной причиной.
- Все дефекты в DEFECTS.md по этому заданию закрыты qa.

## Adversarial-прогон

ADV-001 (ADVERSARIAL_REVIEW.md): ~60 запросов — краевые `art_id` (0, отрицательные,
переполнение int, нечисловые, URL-кодированные), Unicode/XSS/SQL-подобные значения
`author`, нестандартные HTTP-методы, заголовки `Accept`, пачка из 10 конкурентных
запросов к несуществующим статьям, регресс соседних маршрутов. Все ответы штатные,
в логе ни одного трейсбека. Disposition: `REJECTED - чистый прогон: реальных находок
нет, исправлять нечего`. Замечание вне рамок (не находка): `{{ art.content|safe }}`
в `art_author.html` — существующее поведение, не связанное с заданием.
