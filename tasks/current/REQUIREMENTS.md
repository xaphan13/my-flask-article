# Управление статьями: автообнаружение файлов и страница разбора

## Суть

Сейчас каждая статья описывается вручную в `flaskblog/new_articles/articles.yaml`,
а реестр грузится один раз на импорте модуля: новые файлы в `content_art/` сайтом
не замечаются до правки yaml и перезапуска. Нужно: автоматический поиск файлов
статей, страница управления для разбора нераспределённых файлов, перечитывание
реестра без перезапуска сервера.

## Принятые решения (зафиксированы с пользователем 2026-08-28)

1. Вся мета (author, lang, art_id, title, file_name) остаётся в `articles.yaml` —
   формат записей не меняется. Сервер никогда не редактирует файлы статей.
2. Front matter внутри md-файлов полностью игнорируется: не парсится, не
   префиллит форму, не срезается при рендере (ведущий `---`-блок в
   `gemini-pro-fastapi-1.md` продолжает отображаться текстом, как сейчас).
3. Реестр читается с mtime-кэшем: на каждый запрос — один `os.stat` по
   `articles.yaml`; при изменении `(st_mtime_ns, st_size)` — перечитывание.
   Работает при любом числе воркеров.
4. Скан папки `content_art/` на `.md`/`.markdown` выполняется только на странице
   управления; публичные маршруты не сканируют папку и не открывают файлы ради
   меты.
5. `art_id` новой статьи = `int(time.time())` в момент регистрации; коллизия —
   +1 секунда, пока id не свободен.
6. «Добавить все нераспределённые» регистрирует найденные файлы с дефолтами:
   title = имя файла без расширения, author = "", lang = "". Статьи с неполной
   метой скрыты с `/art_home` и отдают 404 по прямому URL.
7. HTML-статьи уходят: `art1.html`–`art4.html` и их записи удаляются; конвейер
   только `.md`/`.markdown`.
8. Страница управления за `@login_required`.

## Что сделать

**backend-dev** (`schema_art.py`, `routes_articles.py`, `articles.yaml`):

- Заменить загрузку-на-импорте функцией доступа к реестру с mtime-кэшем:
  распарсенный список `ArticleLang` + признаки файла в модуле; изменение yaml →
  перезагрузка. При ошибке парсинга (синтаксис сломан ручной правкой) — работать
  на предыдущем состоянии, логировать, не отдавать 500; ошибка видна на странице
  управления.
- Атомарная запись yaml: tmp-файл в той же папке + `os.replace`; формат
  человекочитаемый (как текущий), `allow_unicode`.
- Сканнер папки `content_art/` (только для manage): список `.md`/`.markdown`;
  классификация: зарегистрированные / нераспределённые / записи без файла.
- Маршруты (все `@login_required`):
  - `GET /art_manage` — три раздела: все статьи (id, файл, мета, статус
    полноты), нераспределённые файлы (с формой), записи без файла.
  - `POST /art_manage/add_all` — зарегистрировать все нераспределённые файлы
    (решения 5–6).
  - `POST /art_manage/meta` — file_name + author/lang/title: для
    нераспределённого файла — регистрация с новым art_id; для
    зарегистрированного — обновление меты. `file_name` валидируется по
    результатам скана/реестра — защита от path traversal и опечаток.
- `art_home`: только статьи с полной метой; устаревший `x.dict(...)` заменить
  актуальным API (model_dump или прямая сборка dict).
- `art_author`: 404 при отсутствии записи, файла на диске или полной меты;
  уходит мутация общего `art.content` (объект создаётся на запрос).
- Миграция (одноразово, коммитится): удалить `art1.html`–`art4.html`; из
  `articles.yaml` удалить их записи. Запись art_id 5 (`gemini-pro-fastapi-1.md`)
  не меняется. Инвариант: сайт до/после миграции выглядит одинаково (одна
  статья №5 на `/art_home`).

**frontend-dev** (`flaskblog/templates/`):

- `new_art/art_manage.html` — extends `layout.html`, `show_sidebar`; секции
  «Все статьи» (таблица: id, файл, title, author, lang, статус полноты),
  «Нераспределённые файлы» (по строке с inline-формой author/lang/title),
  «Записи без файла»; кнопка «Добавить все»; для зарегистрированных статей — та
  же форма с префиллом для правки меты. Bootstrap-классы как в соседних
  шаблонах, русский язык.
- Ссылка «Управление» в `_header.html` для залогиненных.

## Вне рамок

- Удаление «записей без файла» кнопкой (чистка yaml вручную, он в git).
- Роли/разграничение доступа кроме `@login_required`; пагинация; поиск по
  тексту; превью неполных статей.
- Docker-сценарий: правки yaml в контейнере эфемерны; задание нацелено на
  локальный запуск.
- Восстановление html-статей (контент остаётся в истории git).
- Смена порядка сортировки `/art_home` (как сейчас — порядок yaml).

## Риски (учесть при реализации)

- Запись yaml из веб-запроса: `file_name` только из результатов скана/реестра;
  атомарная запись tmp+replace; git — страховка.
- Конкурентные POST двух форм: последний атомарный write побеждает, частичного
  файла не бывает; для личного сайта приемлемо.
- Сломанный вручную yaml: кэш держит последнее рабочее состояние, ошибка
  логируется и показывается на manage-странице.
- mtime-кэш сравнивает `(st_mtime_ns, st_size)`, а не голый mtime.

## Критерии успеха

Каждый критерий подтверждается доказательством (curl-вывод, cat, скриншот,
лог) в `tasks/current/e2e/`.

1. Миграция: `art1.html`–`art4.html` удалены; в `articles.yaml` одна запись
   (art_id 5, полная мета). Доказательство: ls + cat в e2e-заметке.
2. `/art_home` → 200, ровно одна статья (№5); `/art/Max/5` → 200;
   нераспределённые файлы на сайте не видны; `/art/Max/999` → 404.
3. `/art_manage` без логина → редирект на `/login`; с логином → 200: «Все
   статьи» — 1 запись, «Нераспределённые файлы» — 3 файла, «Записи без файла» —
   пусто. Скриншот, обе темы.
4. `POST /art_manage/add_all` → в yaml появились 3 записи с различными
   art_id ≈ unix-время; дефолтные title из имён файлов; `/art_home` по-прежнему
   показывает 1 статью (неполные скрыты); manage-страница помечает их неполными;
   файлы статей не изменены (git status чист по content_art).
5. `POST /art_manage/meta` (codex-onefast-review.md, author=Max, title=…,
   lang=Python) → запись в yaml полная, статья появилась на `/art_home`,
   `/art/Max/<art_id>` → 200 с отрендеренным markdown.
6. Правка title в `articles.yaml` вручную в редакторе → после обновления
   `/art_home` показывает новое название (mtime-кэш перечитал yaml без
   перезапуска сервера).
7. `POST /art_manage/meta` с `file_name=../../../etc/passwd` и с несуществующим
   именем → отклонён (4xx/редирект), yaml не изменился.
8. Сломанный yaml (вставить битую строку) → `/art_home` остаётся 200 на
   последнем рабочем состоянии, ошибка в логе и на manage-странице; после
   починки yaml всё восстанавливается.
9. `uv run ruff check .` — без замечаний.
10. `python -c "from flaskblog import create_app; print(len(list(create_app().url_map.iter_rules())))"`
    → `16` (13 + 3 новых маршрута).
11. Регресс: `/`, `/about`, `/login`, `/register` работают как раньше.
